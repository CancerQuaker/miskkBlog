# Vditor Markdown 编辑器改造设计

## 目标

将文章编辑页的 `@uiw/react-md-editor` 替换为 Vditor，默认提供接近 Typora 的即时渲染体验，解决只能编辑源码、正文图片上传不便和写作辅助功能不足的问题。

## 范围

- 默认使用即时渲染（IR）模式，允许切换分屏（SV）和所见即所得（WYSIWYG）模式。
- 提供常用排版工具、全屏、大纲、字数统计和撤销重做。
- 正文图片支持工具栏选择、粘贴和拖拽上传，复用 `articleApi.uploadImage`。
- 使用文章 ID 区分本地缓存；新文章使用独立缓存键，保存成功后清理对应缓存。
- 编辑器样式适配站点主题和后台布局。
- 保留现有文章创建、更新、封面上传及前台 `react-markdown` 渲染链路，不修改后端接口和存储格式。

## 非目标

- 不引入协同编辑、评论批注或服务端自动保存。
- 不为了编辑器扩展能力改造前台渲染器；关闭或避免使用前台不支持的扩展语法。
- 不修改本次范围外的后台页面。

## 方案比较

### 保留 @uiw/react-md-editor 并增强

改动较小，可分屏预览并自行补齐图片上传，但仍是源码编辑体验，不能解决本次核心痛点，因此未采用。

### 替换为 Vditor（已确认）

原生支持 IR、SV、WYSIWYG 三种模式，以及图片粘贴/拖拽上传、大纲、计数和缓存，能直接改善写作体验。代价是需要新增依赖、封装 React 生命周期，并控制编辑器能力与前台渲染的一致性。

## 实施约束与决定

- 在 `frontend/src/components` 封装可复用的 Vditor React 组件，文章页只传值、变更回调、缓存键和图片上传方法。
- 使用 Vditor 自定义 `upload.handler` 调用现有上传 API，按原文件名顺序插入返回的 Markdown 图片语法，失败时给出明确提示。
- React 属性更新与 Vditor 内部输入分开处理，避免每次输入都重建编辑器或重置光标；卸载时销毁实例。
- 新文章和编辑文章使用不同缓存键；异步加载已有文章后再初始化，避免空内容覆盖缓存或正文。
- 保留 CommonMark/GFM 能力，不启用 Mermaid、数学公式等前台暂不支持的功能。
- 保存前从编辑器实例读取最新正文，避免工具栏操作或异步回调造成内容滞后。
- 使用 `npm run build` 验证类型与构建，并在浏览器中验证输入、模式切换、图片上传接入、编辑已有文章和草稿保存流程。

## 待实施细节

具体工具栏排布、主题适配和异常处理由实施者依据现有 Ant Design 页面风格确定，不改变上述已确认范围。
