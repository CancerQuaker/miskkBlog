# 文章互动统计修正设计

## 目标

完善浏览次数、评论数、分享数和当前阅读时长统计，彻底移除累计观看时长功能。保持现有网关接口风格、Redis 浏览量削峰和文章表冗余计数字段。

## 统计口径

- **浏览次数**：同一登录用户或匿名 IP 对同一文章每天只计一次；文章详情展示数据库值与 Redis 待落库增量之和，上报成功后页面即时更新。
- **评论数**：包含顶级评论和所有回复；新增加一，删除回复减一，删除顶级评论扣除自身及全部回复；前端操作成功后同步更新文章头部数字。评论区分页总数仍只表示顶级评论数。
- **分享数**：QQ 成功打开分享窗口、微信二维码成功生成、链接成功复制后才上报；数据库原子累加，前端上报成功后同步更新。
- **当前阅读时长**：仅本次文章页面会话，按真实经过时间计秒；仅页面可见时累计，隐藏时暂停，切换文章时清零。纯前端展示，不上报、不持久化。
- 保留“预计阅读分钟数”，它不属于累计观看时长。

## 方案比较

1. **完整清理并修正计数（已选）**：移除累计时长全链路并提供迁移脚本；计数采用数据库原子更新，浏览缓冲采用原子取出。能同时解决功能冗余和并发覆盖。
2. **保留旧时长结构**：只停用前端功能，升级简单但留下无效代码和存储，不满足彻底移除。
3. **互动实时聚合**：评论和分享每次从日志表计数，一致性强但列表查询成本及改动范围过大。

## 改动范围

- 前端：文章详情增加可见性感知的本次阅读计时；移除文章卡片累计时长；浏览、评论、分享成功后更新本地计数；分享失败不误报。
- 后端：删除 `/watch` 网关、Feign、下游接口及 `WatchDTO`、`WatchRecord`、对应 Mapper 和 Service 方法；移除文章 VO/实体中的 `watchSeconds`。
- 计数：评论、分享和浏览落库改为 SQL 原子增减；浏览量 flush 使用 Redis Lua 原子取出并删除每个 Hash 字段，避免读取后新增增量被误删；删除文章时保留浏览缓冲中的无效增量由 flush 忽略。
- 数据库：新建脚本移除 `t_article.watch_seconds` 和 `t_watch_record`；初始化脚本及种子数据同步删除累计时长字段。迁移脚本只提供，不自动在现有数据库执行。
- 文档：同步更新 README、AGENTS.md、SQL 说明及模块描述中已过时的时长链路。

## 非目标

- 不增加跨会话阅读时长、在线人数或阅读进度统计。
- 不改变浏览量按日去重、评论分页和分享日志的既有业务口径。
- 不为博客服务新增测试脚手架；按项目现有约定通过 Maven 编译、前端构建和实际接口/页面操作验证。

## 验证

- 后端全模块构建通过，前端 TypeScript 与 Vite 构建通过。
- 检查累计时长相关代码和初始化 SQL 无残留。
- 验证浏览去重、评论新增/删除、分享成功/失败、页面隐藏暂停和切换文章清零；可用服务时执行真实接口及页面操作，否则明确说明未验证项。
