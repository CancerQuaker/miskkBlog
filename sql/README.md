# SQL 执行说明

数据层为 **PostgreSQL 单库**：全部 10 张表统一存放在 `miskk_blog`（用户 / 友链 / 文章 / 分类 / 标签 / 评论 / 点赞 / 分享）。

```bash
# 先建库（已存在则跳过）
psql -U postgres -c "CREATE DATABASE miskk_blog ENCODING 'UTF8'"
# 建表 + 种子（可重复执行）
psql -U postgres -d miskk_blog -f sql/miskk_blog.sql
```

docker 部署时无需手动执行：postgres 容器首次启动（空数据卷）会自动跑该脚本（`POSTGRES_DB=miskk_blog`）；
手动补跑用 `docker exec -i miskk-pg psql -U miskk -d miskk_blog < sql/miskk_blog.sql`。

## 脚本行为（可重复执行）

- 建表全部 `IF NOT EXISTS`；用户/友链/分类/标签种子用 `ON CONFLICT ... DO NOTHING/UPDATE` 幂等。
- 种子文章（id 1-4）与评论（id 1-14）按固定 id 段**删除后重灌**：发布/评论时间按执行日相对计算（近 30/14 天摊开），浏览/点赞等计数会重置，不影响种子之外的数据。
- **末尾对每张有显式插 id 的表执行 `setval(pg_get_serial_sequence(...))` 对齐 IDENTITY 序列**——PG 的 `GENERATED BY DEFAULT AS IDENTITY` 允许显式插 id 但不推进序列，不对齐的话应用首次自增插入就会主键冲突。**手工往这些表插过数据后，也要重新跑一遍 setval。**

## 注意

- 种子文章的 `author_id = 1`，对应种子管理员；若你重建了用户表，请同步修改。
- 文章/评论搜索走应用层的 `ILIKE`（不区分大小写）；点赞防并发靠 `t_article_like (article_id, user_id)` 唯一索引。
- 修改密码也可登录后在「个人资料」中自助修改。
